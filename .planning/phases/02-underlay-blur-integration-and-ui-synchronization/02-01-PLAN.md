In `ui/webgl/context.js`, create a helper function to initialize FBOs with attached textures. This function must explicitly set texture filtering to `gl.LINEAR` to avoid blocky artifacts (Pitfall 1) and size the textures at a reduced resolution (e.g., canvas.width / 4) for performance (Pitfall 3).

In `ui/webgl/renderer.js`, implement the 4-pass "ping-pong" blur pattern described in `02-RESEARCH.md`. Crucially, you must separate the render loop into two distinct stages to achieve strict visual parity:
1. **Blurred Stage:** Render the background elements (Aurora gradients) using the `BATCH` program into the first FBO. Then, use the `PRIMITIVE` shader to perform 4 blur passes, "ping-ponging" between the two FBOs.
2. **Sharp Stage:** Render the UI primitives (button outlines, text, glyphs) using the `BATCH` program directly to the default canvas framebuffer (the screen), ensuring they remain sharp and are drawn *on top* of the blurred background.

This implements decision D-04 and addresses the visual parity requirement.
