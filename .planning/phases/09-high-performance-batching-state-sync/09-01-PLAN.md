# Plan: 09-01-PLAN.md — Layout Tracking & State Sync

**Phase:** 09 - High-Performance Batching & State Sync
**Focus:** Non-blocking DOM geometry synchronization to the Store using `ResizeObserver`.

## Goal
Eliminate `getBoundingClientRect` calls from the render loop by implementing a `LayoutManager` that tracks element geometry asynchronously and updates the global Store.

## Requirements
- **REQ-WGL-05**: Batch Rendering (100+ items support).
- **REQ-WGL-06**: Animation Interpolation.

## Success Criteria
1.  **Async Tracking**: A singleton `ResizeObserver` monitors all calculator UI elements.
2.  **State Sync**: Store's `state.layout` is updated with `{x, y, w, h}` whenever an element changes.
3.  **No Thrashing**: Store updates do not trigger immediate re-renders; they are batched for the next WebGL frame.
4.  **Verifiability**: `console.log` in the render loop shows layout data is pulled from the Store, not the DOM.

## Technical Strategy
-   Implement `services/layout.js` as a singleton.
-   Use `ResizeObserver`'s `contentRect` and `target.offsetTop/offsetLeft` for geometry.
-   Update `services/store.js` to include a `layout` map (element ID -> rect).
-   Modify `ui/uimanager.js` to register elements with the `LayoutManager` during initialization.
